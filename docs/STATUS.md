## 데이터와 운영 경계

- 사용자 확인은 `getCurrentUser()` → `getOwnerId()`/`tryGetOwnerId()`; 서비스 역할 쿼리는 owner 조건을 별도로 유지한다.
- Auth 연결·anon 4개 테이블 0행·Storage 연결 확인. 임시 인증 사용자 2개로 과목·자료·일정·문제 조회/삭제/위조 소유자 삽입 차단, 학기 성적 필드 왕복, 실제 TOTP를 검사해 23개 통과했다. 모든 테이블의 모든 작업 검증을 뜻하지 않는다.
- 운영 스키마 이력은 0001~0037이 로컬과 일치한다. 0028은 학기·학점·등급, 0029는 0학점 과목, 0030은 사용자별 월간 AI 사용량 집계, 0031은 동시 요청 비용 예약과 실제 비용 자동 정산, 0032는 핵심 작업의 1회 자동 재시도, 0033~0034는 FSRS 카드·리뷰 이력과 MFA 제한, 0035는 학기 목표·회고, 0036은 풀이별 시험 회고, 0037은 작업 단계·진행률 이력을 추가했다.
- Upstash 미설정 시 메모리 sliding window. 제한 저장소 장애 시 503으로 작업 시작을 거절한다. 운영에서는 실제 DB 비용과 활성 예약액을 사용자별 잠금 안에서 합산해 월 $3 상한을 적용한다. 실제 단일 요청 비용이 예약액을 넘는 차이만큼은 상한을 초과할 수 있어 운영 분포에 맞춰 `AI_REQUEST_RESERVE_USD`를 조정한다.
- 서버 개발 모드에서는 fallback 사용자가 있으므로 개발 화면이 열린다는 사실만으로 실제 로그인이 검증되지 않는다.
- 설정의 내보내기는 로그인한 사용자 소유 데이터만 서비스 역할 쿼리의 `owner_id` 조건으로 모은다. JSON에는 자료에서 추출한 본문과 채팅 내용이 포함되므로 사용자가 직접 보관 위치를 선택해야 한다.
