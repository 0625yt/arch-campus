# 즉시 완성도 보완 실행 계획 — 2026-09-29

## 목표

이미 준비된 기반을 활용해 사용자가 바로 체감하는 막힘을 먼저 없앤다. 이번 작업은 실패한 요약 자료를 현재 화면에서 다시 올릴 수 있게 하고, 실제 파서가 지원하는 파일 형식과 업로드 정책을 일치시키는 데 집중한다.

## 이번 구현 범위

1. 요약 오류 카드 안에 새 파일 교체 영역을 추가한다.
2. 새 자료의 Storage 업로드와 DB 등록이 끝난 뒤에만 기존 실패 자료를 삭제한다.
3. 지원하지 않는 형식, 빈 파일, 60MB 초과 파일은 업로드 전에 설명한다.
4. DOCX·PPTX·XLSX·XLSM·이미지를 일반 업로드와 합본 업로드에서 허용한다.
5. 구형 DOC·PPT·XLS와 HWP/HWPX는 변환 안내를 유지한다.
6. 교체 성공·실패 흐름, 타입 검사, 단위 검사, 빌드, 문서 링크를 검증한다.

## 수용 기준

- 실패한 자료 상세 화면을 벗어나지 않고 파일을 다시 선택할 수 있다.
- 새 파일 등록이 실패하면 기존 자료가 남는다.
- 새 파일 등록이 성공하면 같은 과목·제목·자료 종류로 분석이 시작되고 새 자료 화면으로 이동한다.
- 최신 Office 파일이 기존 파서까지 도달하며 업로드 완료 단계에서 거부되지 않는다.
- 코드·브라우저 회귀·프로덕션 빌드가 모두 통과한다.

## 이번 범위 밖의 결정

월별 무료 횟수, Pro 가격, 초과 허용 여부는 사업 정책에 따라 사용자 경험이 달라진다. 임의의 하드캡을 먼저 넣지 않고 사용량 원장과 상품 정책을 함께 설계한다. 결제, 외부 캘린더, 푸시는 외부 계정과 운영 비밀값이 필요한 후속 작업으로 유지한다.
