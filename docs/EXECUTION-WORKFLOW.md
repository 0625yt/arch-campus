## 실행 규칙

1. 아래 순서대로 구현 → 해당 회귀 검사 → 결과 기록을 진행한다.
2. 외부 계정·비밀값·제품 정책이 필요한 항목은 필요한 조건을 명시하고 다음 실행 가능한 단계로 이동한다.
3. 실서비스 검사는 임시 계정과 가상 자료만 사용하고, 성공·실패 모두 계정과 데이터를 정리한다. 키·세션·복구 토큰은 출력하거나 커밋하지 않는다.
4. 기본 검사는 외부 AI 호출 없이 실행한다. 실제 AI 평가는 명시적 명령으로 분리하고 결과·실패·추정 비용을 기록한다.
5. 변경 뒤 타입·단위·문서·빌드·관련 화면을 확인한다. 배포·원격 CI 결과는 로컬 결과와 구분한다.

## 실행 명령

실제 인증/API 검사는 로컬 서버가 필요하다. 별도 터미널에서 `npm run dev -- --port 3010`을 실행하거나 `E2E_BASE_URL`로 검증 대상을 지정한다. `.env.local`의 기존 키를 사용하며 토큰은 출력하지 않는다.

```bash
npm run workflow:auth
npm run workflow:files
npm run workflow:ai
npm run workflow:jobs
npm run workflow:limits
npm run test:summary-chunks-live
npm run test:summary-quality-live
npm run workflow:worker
npm run test:quiz-job-live
npm run test:pwa
npm run workflow:quality
npm run report:ai-costs
```

각 명령은 내부 검사를 순서대로 실행하고 첫 실패에서 중단한다. `workflow:files`의 OCR과 `workflow:ai`는 실제 AI 호출 비용이 발생하므로 기본 CI/단위 검사에서 자동 실행하지 않는다. 원시 생성 진단(`test:prompt-stress-live`)은 생성·보충·검수 파이프라인과 구분한다.

`workflow:limits`는 기존 정책을 유지한 공유 제한의 단위·임시 DB 스키마·인증 HTTP 검사를 순서대로 실행한다. DB/HTTP 검사에서는 AI를 호출하지 않는다. `test:summary-chunks-live`는 실제 AI 비용이 발생하며 성공 구간 수·실패 구간 안내·중복 없는 비용을 검사한다. 모든 구간의 요약 품질이 통과한다는 뜻은 아니다. 0039는 검증된 연결 DB에 적용했다. 별도 DB에서 새 코드를 실행한다면 마이그레이션을 먼저 적용해야 하며, 누락 시 운영 요청은 503으로 차단한다.

`workflow:jobs`는 관련 단위 → 체크포인트 DB → 결과 저장 DB → HTTP 순서다. 0038 검사는 트랜잭션 안에서 가상 데이터를 만든 뒤 롤백한다. 0040 검사는 함수 정의를 트랜잭션으로 확인하고 실제 임시 계정/자료를 만든 뒤 동시 완료·전체 롤백·소유자·실행 횟수·권한을 검증하며 마지막에 임시 계정을 삭제한다. API 검사는 빈 자료로 수행하므로 AI 호출·비용 예약이 발생하지 않는다. 0038·0040 RPC는 검증한 로컬·Preview 연결 DB에 적용했으며, 별도 DB가 있다면 코드 실행 전에 적용해야 한다. `test:quiz-job-live`는 실제 AI 비용이 발생하고 작업·문제·생성 기록의 저장 일치를 검사한다. 로컬 개발 모드의 익명 fallback은 보안 검사에서 생략하고 실제 Preview에서 401을 확인한다. `test:pwa`는 공개 안내·아이콘만 캐시하며, 학습 데이터의 오프라인 열람·저장이나 실제 스마트폰 설치를 검증하지 않는다.

작업 재개 시 위 상태표에서 다음 실행 가능한 항목을 고르고 해당 단계의 증거를 보고서에 추가한다. 이 문서는 예약 실행이나 외부 설정을 자동 생성하지 않는다.

`workflow:worker`는 서버 라우트 단위 → 임시 스키마의 전역 DB 선점 → 범위를 제한한 실제 HTTP 순서다. 예약/실제 AI 검사는 후속 보고서의 별도 명령을 사용한다. 운영 예약 활성화는 새 코드와 실행 키의 인증된 준비 상태가 확인된 뒤 `worker:enable`로 수행한다.
