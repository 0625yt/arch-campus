# 시험 준비실과 오늘의 공부

## 사용하는 흐름

홈과 공부 공간의 **시험 준비실**에서 과목·시험 날짜·자료를 선택한다. 등록된 확정 시험을 선택하면 날짜가 연결된다. 공지에서 확인한 범위와 제외 부분은 최대 200자로 적는다. 긴 일정 메모는 그대로 확인할 수 있으며 조용히 잘라서 출제 범위로 사용하지 않는다.

자료마다 원문·개념 확인 15분, 5문제 점검 10분, 개념 설명 5분을 기본 작업으로 만든다. 이 시간은 실제 자료의 난도나 학생의 학습 능력을 측정한 값이 아니다. 하루 시간은 15~180분이며 여러 시험이 하나의 시간을 나눠 쓴다. 가까운 목표일을 우선하고 작업 순서를 유지한다. 목표일 당일도 포함하므로 시험 시작 시각과 공부 가능한 시간은 별도로 확인해야 한다.

Today와 준비실에서 집중 타이머를 시작하거나 작업을 완료·내일로 미룬다. 시간 변경과 미룸은 남은 작업을 다시 배치하며 완료 기록을 보존한다. 목표일까지 배치되지 않은 분량은 별도로 표시한다. 타이머는 일시정지·재개를 지원하고 만료만으로 작업을 완료하지 않는다. 타이머 자체는 현재 화면의 메모리에서 실행되며 새로고침 후 자동 복원하지 않는다.

문제 점검 작업은 저장된 범위와 최대 6개의 같은 과목 자료를 기존 생성 폼으로 연결한다. 범위 로딩이 끝나기 전에 생성할 수 없다. 로딩 실패 시 직접 확인·입력을 선택해야 재개할 수 있다. 생성 요청은 사용자가 직접 실행한다. 풀이 결과에서는 헷갈린 주제와 함께 작업을 완료하고 Today로 돌아갈 수 있다. 완료한 작업 수는 이해도나 예상 점수가 아니다.

도래한 FSRS 복습은 최대 5문제 단위로 진입할 수 있다. 남은 도래 문제는 기존 복습 큐에 유지된다. 계획은 최대 8개를 활성화하고 총 30개를 저장한다. 보관은 기록을 유지하며 보관 기록의 삭제는 화면에서 두 단계로 확인한다. 학업 JSON 내보내기에 공부 계획과 메모도 포함한다.

## 저장과 운영 적용

- 새 파일: [0043_study_workspaces.sql](../supabase/migrations/0043_study_workspaces.sql).
- 기존 과목·자료·일정 및 MFA 함수가 적용된 DB가 필요하다. 푸시용 0042나 전송 키에는 의존하지 않는다.
- **운영 DB에는 아직 적용하지 않았다.** 저장소가 준비되지 않으면 저장 성공을 가장하지 않고 오류와 재시도 동선을 제공한다.
- 저장소 추가 후 운영 배포를 해야 실제 서비스에서 제공된다. 저장소의 규칙에 따라 관리자가 Supabase 대시보드에서 0043 SQL을 실행하고 이후 검증한다.
- 스키마를 아직 적용하지 않은 환경의 기존 학업 내보내기는 `studyWorkspace: null`로 유지한다. 다른 저장 오류는 전체 내보내기를 실패 처리한다.

## 사용자 경계

`study_workspaces`는 owner당 한 행이다. API는 세션 사용자만 사용하며 과목·자료·확정 시험의 소유권과 자료의 과목을 확인한다. 일반 DB 클라이언트에는 쓰기 권한이 없고 읽기에는 owner RLS와 MFA 정책을 적용한다. 서버 쓰기에도 새 참조의 소유권을 트리거로 확인한다. 삭제된 원문이 있는 기존 기록도 보관할 수 있다.

읽기·갱신 응답은 private/no-store다. 범위나 메모를 URL에 넣지 않고 계획·작업 ID로 연결한다. 저장은 관찰한 revision과 owner를 비교해 원자적으로 갱신하며 충돌하면 최신 계획을 불러온 후 재시도하게 한다. 기본 공유 요청 제한과 교차 출처 브라우저 쓰기 차단을 적용한다.

계획을 만들거나 배치·완료·미루는 동작에는 새 AI 호출이 없다. 문제 생성과 풀이 채점은 기존 모델·비용 보호 경로를 사용한다.

## 검증 명령

```sh
npm run test:study-plans
npm run test:study-plans-db
npm run test:study-plans-browser
```

DB 검사는 `.env.local`의 연결에서 임시 스키마를 만들고 제거한다. 운영 테이블·사용자·일정은 변경하지 않는다. 브라우저 검사는 개인 저장 응답과 가상 자료를 모의하며 실제 운영 저장·AI 품질 검사와 구분한다. 일부 생성 폼·풀이 결과 검사는 운영에서 차단된 `/dev/campus-preview`를 사용한다.
