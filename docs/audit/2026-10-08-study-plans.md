# 시험 준비실·Today 공부 실행 구현과 검증

2026-10-08 · 로컬 코드 기준 · 운영 DB 적용과 배포는 미실행.

## 바뀐 사용자 경험

시험 준비실에서 시험 날짜·범위·같은 과목의 강의자료를 묶는다. 여러 시험의 작업을 공통 하루 시간에 배분하고 Today에서 바로 시작한다. 완료·내일로 미룸·시간 변경은 기록을 보존하며 남은 공부의 배치를 바꾼다. 목표일까지 배치할 수 없는 분량도 표시한다.

집중 타이머는 일시정지·재개를 지원하고 만료만으로 완료하지 않는다. 공부 메모를 완료 기록과 함께 저장한다. 문제 점검 작업은 범위 로딩을 기다린 뒤 기존 묶음 생성 폼으로 연결한다. 생성한 문제의 풀이 결과에서는 헷갈린 개념을 기록하고 작업 완료 후 Today로 돌아간다. 도래한 FSRS 복습은 최대 5문제부터 시작할 수 있다.

끝난 계획을 보관하고, 필요 없는 보관 기록은 명시적인 삭제 확인 후 지운다. 기존 JSON 학업 내보내기에도 공부 계획과 메모를 추가했다. 요약이 없다는 사실을 학생이 자료를 안 읽었다는 표현으로 보여주던 부분도 수정했다.

기본 작업 시간·작업 완료 수는 자료 전체의 학습량이나 학생의 이해도를 측정한 결과가 아니다. 기존 AI 벼락치기 결과의 자동 가져오기, 오개념에 따른 자동 변형 문항 생성, 과제 초안 검토는 이번 변경에 포함하지 않는다. 현재 제공 범위와 한계는 [기능 가이드](../STUDY-PLANS.md)를 따른다.

## 데이터와 권한

- [0043](../../supabase/migrations/0043_study_workspaces.sql): owner당 공부 공간 한 행, 제한된 계획 JSON과 revision. 일반 DB 클라이언트 쓰기는 금지하고 읽기에 owner/MFA 정책을 적용한다.
- [DAL](../../src/lib/data/study-plans.ts): 소유자 조회·실제 빈 상태와 장애 구분·최초 삽입 충돌·owner/revision 조건 갱신.
- [API](../../src/app/api/study-plans/route.ts): 세션, 엄격한 입력, 소유 과목·자료·확정 시험 날짜, 교차 출처, 공유 요청 제한 검사. 소유자는 요청 본문에서 받지 않는다.
- [계획 로직](../../src/lib/study-plan.ts): KST 날짜, 공통 시간, 목표일 우선 배분, 완료 시간 보존, 미룸과 기한 초과 분량.
- 새 참조의 DB 소유권 재검사와 revision 증가 검사. 삭제된 원문의 기존 기록은 보관 가능.
- scope/메모를 URL에 넣지 않고 계획·작업 ID로 연결하며 응답은 private/no-store. 개인 데이터를 PWA 캐시에 추가하지 않았다.

계획 생성·배치·상태 저장에는 AI를 추가 호출하지 않는다. 기존 문제 생성·채점 모델과 비용 보호 경로는 유지한다.

## 실제 실행한 검사

| 검사 | 결과 | 범위 |
|---|---|---|
| 전체 Vitest | 520 통과 / 외부 AI 16 생략 | 기존 회귀 포함. 새 계획·DAL·API는 27개 |
| 전체 Playwright | 111 통과 / 별도 인증 3 생략 | 모바일 390·태블릿 834·노트북 1280. 새 흐름은 24개 |
| 임시 DB | 13 통과 | RLS·MFA·쓰기 금지·참조 소유권·시간 상한·12개 동시 저장 중 하나만 수락·원문 삭제 후 보관·계정 삭제 cascade |
| 실제 로컬 운영 모드 HTTP | 4 통과 | 새 API GET/POST 비로그인 401, 생성·결과 개발 화면 404 |
| 실제 로컬 개발 모드 HTTP | 4 통과 | 새 저장소 미적용 GET 503, 잘못된 입력 400 두 건, 교차 출처 403. 저장 요청은 실행하지 않음 |
| 타입·프로덕션 빌드·전체 Biome | 통과 | 최종 소스 기준 |
| 문서·diff 공백 검사 | 통과 | 문서의 파일 링크와 변경 공백 검사 |

브라우저 검사는 공부 저장 응답과 가상 자료를 모의했다. 시험 범위가 로딩되는 동안 생성 금지, 범위·추가 자료의 실제 요청 본문, 풀이 결과의 개념 메모와 작업 완료, 재접속, 연결 실패의 입력 보존, 타이머 만료의 수동 완료, 다크 모드·동작 줄이기·접근성을 확인했다. 실제 AI의 범위 준수나 학생의 반복 사용 효과를 검증한 결과는 아니다.

DB 검사는 임시 스키마를 생성하고 제거했으며 운영 테이블·사용자·일정을 수정하지 않았다. 새 기능의 저장은 운영 DB에서 실행하지 않았다. 기존 공부 공간의 회귀 테스트는 원본을 유지하고 새 테스트는 `e2e/study-plans.spec.ts`로 분리했다.

## 운영에 남은 단계

1. 기존 스키마가 준비된 DB에 관리자가 0043 SQL을 적용한다. 푸시 0042 설정에는 의존하지 않는다.
2. 코드 배포 후 실제 인증 계정으로 생성→미룸→풀이→완료→재접속과 JSON 내보내기를 확인한다.
3. 실제 학생의 자료로 기본 분량·범위 입력·문제 품질·반복 사용을 평가한다. [사용자 가치 검토](2026-10-08-student-value.md)의 검증 계획 참고.

커밋·PR 생성·운영 배포는 하지 않았다. 작업 시작 전에 있던 알림·보안 수정과 사용자 설정 변경을 보존했다.
