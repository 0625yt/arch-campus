# 엄격 검증 후 보완 — 2026-09-22

이번 기록은 [최초 점검](2026-09-17-feature-audit.md)의 후속이다. 코드 수정 완료와 운영 적용 완료를 구분한다. 변경 코드는 아직 운영에 배포하지 않았다.

## 고친 동작

- **MFA**: `/auth/mfa`에서 등록한 TOTP를 확인한다. proxy와 서버 사용자 조회가 등록 계정의 AAL1 접근을 거절한다. 개발용 계정으로 우회되지 않는 검사도 추가했다. 리다이렉트에서 갱신 쿠키와 복귀 경로를 보존한다. QR은 HTML 삽입 대신 이미지로 표시하고 등록 취소 시 미확인 factor를 정리한다.
- **작업 실행**: pending 작업을 원자적으로 선점해 같은 작업을 두 worker가 실행하지 않게 했다. 늦은 실패/완료가 이미 끝난 상태를 덮어쓰지 않는다. 등록 경쟁에서 unique 충돌이 나면 기존 작업을 재사용한다. 상태 저장 실패도 무시하지 않는다. 프로세스 종료 후 자동 재개 큐까지 구현한 것은 아니다.
- **비용 방어**: 호출 제한 저장소가 실패하면 503과 재시도 안내를 반환한다. 메모리 제한에서 다른 정책의 만료시간을 잘못 적용하던 정리 로직과 키 상한도 수정했다. 분산 제한·월 비용 쿼터는 여전히 별도 작업이다.
- **접근성·조작**: 입력 라벨 연결, 모달의 포커스/ESC, 메뉴 키보드 처리, 편집 항목의 안정적인 ID, 생성 결과의 중복 가능한 키를 수정했다. 취소 버튼에서 Enter를 눌렀는데 삭제 확인이 실행되던 이벤트 처리도 제거했다.
- **읽기 쉬운 움직임**: 실제 로그인 화면 검사에서 등장 애니메이션 중 글자 대비가 무너지는 문제가 발견됐다. 대시보드는 글자를 흐리게 하지 않고 이동 효과를 사용하며 링크 색의 대비도 보정했다. 검사 시간이나 대비 기준을 낮추지 않았다.
- **의존성**: Next 16.3.3, OfficeParser 8, Vitest 4.1.11 및 호환 패치 적용. npm 10의 peer 처리 오류는 별도 npm 11 실행으로 해결했으며 전역 도구나 peer 검사를 변경하지 않았다. ExcelJS의 uuid만 11.1.1로 제한해 보안 문제를 해소했다. 실제 XLSX 확장 조건부 서식 저장/재읽기 검사로 호환성을 검증한다.

## 운영 반영 전에 남은 필수 항목

1. `.env.local`의 `SUPABASE_DB_URL` 갱신. 현재 연결 주소는 tenant/user not found이며 Supabase CLI 로그인도 설정되지 않았다. 사용자에게 비밀 값을 채팅으로 보내지 말고 환경 파일에 반영하도록 요청했다.
2. `npm run test:db-security` 실행. 테스트는 임시 사용자/행과 0027 정책을 트랜잭션 안에서 확인하고 전부 rollback한다. 운영 적용 완료 검사가 아니다.
3. 0027 MFA restrictive policy 적용 후 DB 직접 접근 검증. 현재 앱 서버의 MFA 보호만으로 DB까지 보호됐다고 판정하지 않는다. 이 마이그레이션은 아직 실행하지 않았다.
4. 운영 분산 호출 제한·월 비용 상한 설정, 사용자 격리의 나머지 테이블/작업 검사, Google OAuth·메일 왕복.
5. 원격 CI 실행 및 검증된 변경의 운영 배포. 로컬 통과와 원격 배포를 같은 것으로 기록하지 않는다.

## 재현과 자동화

```sh
npm run check
npm test
npm run build
npm run test:e2e -- --workers=2
npm run check:docs
npm audit --audit-level=moderate
npm run test:live-auth
npm run test:authenticated-browser
npm run test:live-ai
npm run test:db-security
```

live 검사는 `.env.local`의 서비스 설정을 사용한다. Auth/브라우저 검사는 전용 임시 계정을 생성하며 메일을 발송하지 않고 finally에서 정리한다. SQL 검사는 전부 rollback한다. AI 검사는 소량의 실제 모델 요청 비용이 발생한다. CI에는 코드 규칙·단위·문서·보안·빌드·기본 브라우저 검사를 추가했다. 실제 서비스 검사는 별도 실행해 자격 증명이 없는 상태를 통과로 오인하지 않는다.
