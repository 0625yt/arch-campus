# 대학생 사용자 가치와 제품 개선 검토

검토일: 2026-10-08 · 근거: 현재 저장소 구현, 공개 조사, 대학 공식 지침, 경쟁사 공식 발표.

이 문서는 제품 판단과 검증할 가설을 정리한다. 승인된 로드맵, 가격, 학교별 정책을 변경하지 않는다. 구현 여부는 [STATUS.md](../STATUS.md), 출시 전 기술 과제는 [서비스 점검](2026-10-07-service-gaps.md)을 함께 참고한다. 이번 작업에서는 제품 코드를 변경하지 않았다.

## 1. 현재 가치에 대한 판단

**강의자료 중심으로 시험을 준비하는 대학생에게 쓸 만한 가치는 있다. 다만 많은 대학생이 계속 돌아오거나 별도로 비용을 지불할 정도의 가치는 아직 확인되지 않았다.**

자료 업로드, 출처를 확인할 수 있는 요약·문제, 오답, FSRS 복습, 강의계획서 일정 추출은 서로 이어질 수 있는 좋은 기반이다. 그러나 학생이 시험 범위를 정하고, 오늘의 공부를 시작하고, 끝낸 내용과 못 끝낸 내용을 다음 날에 반영하는 과정에는 수동 연결이 남아 있다. 시험 직전에 결과물 하나를 얻고 떠나는 사용과 학기 내내 사용하는 습관을 구분해야 한다.

현재 확인한 코드와 기술 테스트는 기능의 존재와 일부 정상 동작을 보여준다. 실제 학생의 반복 사용, 학습 성과, 지불 의사에 대한 증거는 별도로 필요하다.

첫 타깃은 여러 이론 과목의 PDF·PPT 자료로 시험을 준비하면서 통학·아르바이트 등으로 시간이 제한된 학부생을 권한다. 학년보다 자료와 평가 방식이 중요하다. 계산·코딩 중심 과목, 논술 중심 과목, 실기·스튜디오 과목은 필요한 피드백이 달라 같은 학습 문제로 합치지 않는다.

## 3. 경쟁 전제의 재검토

Google은 2026년 6월 강의자료 기반 진단 문제, 짧은 학습 단위, 풀이 결과에 따라 갱신되는 학습 계획을 공식 발표했다. [Google 발표](https://blog.google/products-and-platforms/products/education/iste-students-2026/)

8월에는 강의계획서의 시험·과제 날짜를 사용자 허가 후 Google Calendar에 반영하는 기능도 예고했다. 해당 발표만으로 모든 계정에 실제 활성화됐다고 단정하지는 않는다. [8월 공식 발표](https://blog.google/innovation-and-ai/products/gemini-app/student-offer-google-ai/)

NotebookLM은 2026년 7월 Gemini Notebook으로 이름이 바뀌었다. 따라서 예전 경쟁사 이름과 기능표를 그대로 사용해서는 안 된다. [공식 변경 안내](https://workspaceupdates.googleblog.com/2026/07/notebooklm-now-gemini-notebook.html)

에브리타임의 공식 앱 설명에도 시간표, 알림, 학점 관리, 강의평가·시험 정보 등이 있다. 이는 개발사의 기능 설명이며 이번에 직접 사용성을 비교한 결과는 아니다. [공식 앱 설명](https://play.google.com/store/apps/details?hl=ko&id=com.everytime.v2)

[PRODUCT.md](../PRODUCT.md)의 과거 전략 중 경쟁사가 특정 기능을 절대 못 한다는 표현, AI를 잘 못 쓰는 학생의 비율, 성적 데이터 독점·성장·기업가치 관련 주장은 제품 의사결정의 근거로 삼기 어렵다. 문서 상단도 과거 전략 가설임을 명시하고 있다.

**한국어 지원이나 기능 통합만으로 경쟁 우위가 성립하지 않는다.** 실제 교수 공지의 범위·예외·평가 기준, 여러 과목의 충돌하는 마감, 학생의 제한된 시간, 원문에 근거한 오답 교정까지 연결했을 때 기존 도구보다 설정과 검증의 수고가 줄어드는지를 비교해야 한다. 이 방향도 경쟁사가 따라올 수 있으므로 실제 정확도와 사용 경험의 증거가 필요하다.

## 5. 우선순위 제안

여기서 우선순위는 사용자 가치 검증 순서다. 보안·인증·업로드·운영 안정성 등 출시 필수 조건의 우선순위를 낮추는 뜻이 아니다. 모든 항목을 한꺼번에 구현하는 계획도 아니다.

### 먼저: 믿을 수 있는 입력과 학습 상태

실제 강의자료로 추출 누락, 수식·표 손상, 출처 위치, 정답·복수 정답, 범위 밖 문제를 사람이 점검한다. 자료가 읽히지 않은 페이지는 명확히 표시하고 수정·재입력할 수 있어야 한다. 인용 문자열의 존재는 정답의 의미상 정확성을 보장하지 않는다.

특히 현재 `semester-safety.ts`의 일부 “안 본 자료” 판단은 `!hasSummary`에 기반한다. **요약이 없다는 사실로 학생이 자료를 읽지 않았다고 판단할 수 없다.** 표시를 관측 가능한 상태와 맞추고, 실제 이해도는 풀이·자기 점검 등의 근거로 구분해야 한다. 확인하지 않은 학습 상태를 시험 준비율이나 예상 학점으로 표현하지 않는다.

푸시 코드가 있다는 사실과 학생 기기에서 알림을 받을 수 있다는 사실도 구분한다. 현재 푸시는 운영 설정·배포·실기기 검증이 남아 있고 매일의 FSRS 복습 알림은 구현 범위에 포함되지 않는다. [현재 기술 과제](2026-10-07-service-gaps.md)

### 1순위: 한 시험의 범위부터 오늘의 실행까지

최소 단위는 **한 과목, 한 시험, 연결된 자료, 짧은 진단, 오늘의 작업**이다.

1. 학생이 시험 날짜와 범위의 근거를 확인한다.
2. 자료 전체를 요약하기 전에 소수의 진단 문제로 현재 상태를 확인한다.
3. Today에서 가용 시간에 맞는 작업을 바로 시작한다.
4. 풀이·완료·미룸 결과가 해당 시험의 기록에 남는다.
5. 다음 접속에서는 이전 결과와 남은 마감·시간을 반영한다.

예시 가설: “자료구조 중간고사 D-6, 3~7주차, 오늘 40분”을 입력하면 약점 확인 10분, 아직 점검하지 않은 단원 15분, 관련 개념의 다른 문제 10분, 정리 5분을 제안한다. 15분 작업을 못 끝냈으면 남은 일정과 시간이 허용하는 다음 시간에 다시 배치한다. 이는 실제 사용자 데이터나 검증된 효과가 아니라 제안 흐름이다.

첫 온보딩도 이 흐름과 함께 줄이는 것이 좋다. 가입 후 프로필과 전체 학기를 먼저 채우게 하기보다 본인 자료에서 첫 문제를 풀어보는 데 필요한 입력을 최소화한다. 다른 과목까지 확장하는 것은 첫 도움이 확인된 뒤로 미룬다.

### 2순위: 오답을 이해로 바꾸는 짧은 복습

기존 FSRS에 하루 5분 정도의 실행 동선을 연결한다. 정답을 보기 전에 자기 답과 이유를 적게 하고, 원문과 연결된 설명 뒤에 표현·숫자·조건이 다른 문제를 풀게 한다. 반복해서 같은 문항을 알아보는 것과 새 문제를 풀 수 있는 것을 구분한다.

계산·코딩·서술형은 서로 다른 검토 기준이 필요하다. 모든 학과에 같은 품질을 주장하기 전에 초기 타깃 과목에서 검증한다.

### 3순위: 제출 전 검토와 AI 활용 내역

기존 요구사항 체크리스트에 **학생이 쓴 초안**을 연결한다. 필요한 절·자료·분량·제출 형식이 빠졌는지 공지의 원문 근거와 함께 보여준다. 확인하지 못한 항목은 미확인으로 남긴다. 논문 존재나 인용의 정확성을 확인하지 못했으면 확인됐다고 표시하지 않는다.

과제별로 실제 사용 도구·버전·일시·목적·관련 대화와 학생의 검증·수정 메모를 묶어 내보내는 기능을 검증한다. 기록은 실제 생성 시점에 남긴 정보여야 하며 나중에 추정해서 채우면 안 된다. 학교별 양식 수용 여부는 별도로 확인한다. 문장을 바꾸거나 증빙서를 내보내는 것만으로 해당 과제의 AI 사용이 허용되는 것은 아니다.

### 이후: 공지 수집·기존 캘린더 연결·팀플

- 공지 입력을 기존 요구사항 분석·일정 추출과 연결한다. 학교 계정 정보를 수집하는 LMS 연동 전에 붙여넣기와 사진 입력에서 반복 사용을 검증한다. 공지 변경·예외 날짜는 학생이 확인할 수 있어야 한다.
- 기존 캘린더와 함께 쓸 수 있게 한다. 현재 ICS 내보내기는 있지만 가져오기·양방향 동기화는 같은 기능이 아니다. 가져오기와 변경 확인부터 범위를 좁혀 판단한다.
- 팀플은 시간 투표, 담당자·내부 마감·공유 체크리스트, 합의 기록부터 검증한다. 기존 메신저로 공유할 링크가 있으면 모든 팀원이 새 채팅 도구로 이동할 필요가 줄어든다. 작업 기록을 객관적 기여도 점수나 무임승차 판정으로 취급하지 않는다.
- 졸업 요건·장학금·진로 지원은 필요성이 있을 수 있으나 학교별 공식 정보의 최신성 관리가 추가된다. 현재 학습 흐름의 사용 증거를 확보한 뒤 별도의 요구 검증을 권한다.

## 6. 지금 늘리지 않을 기능

범용 글쓰기 위저드의 수, 대량 문제 생성, 독립적인 새 커뮤니티·메신저·채용 정보 서비스, 사용 가치 확인 전의 초대 보상·결제 기능을 먼저 늘리지는 않는 편이 좋다. 기존 사용자 흐름이 끊기는 원인이 결과물 종류의 부족인지부터 확인해야 한다.

학생의 비용 부담을 고려해 기본 사용에서 어떤 도움을 받을 수 있고 언제 제한이 적용되는지 명확히 보여줄 필요는 있다. 실제 지불 의사를 확인하기 전 가격이나 전환율을 확정하지 않는다. 재방문을 늘리기 위한 알림도 완료 가능한 작업과 연결되어야 한다.

## 7. 실제 학생에게 확인할 방법

**15~20명의 타깃 학생에게 실제 시험·과제 자료로 약 2주간 사용하게 하는 검증을 제안한다.** 표본과 기간은 이번 제품 판단을 위한 제안이며 업계 기준이나 통계적 대표성을 뜻하지 않는다.

시작 인터뷰에서는 마지막 시험·과제 한 건을 재현한다. 자료가 어디에 있었는지, 어떤 도구를 썼는지, 가장 오래 걸린 단계, 틀린 AI 답을 확인한 방식, 누락한 요구사항, 통학·일로 공부를 바꾼 날을 구체적으로 확인한다. “이런 기능이 있으면 쓰겠나”라는 답만으로 개발 우선순위를 정하지 않는다.

비교 과제는 동일한 본인 자료와 목표를 가지고 기존 도구 조합 및 우리 흐름으로 공부를 준비하고 실행하는 것이다. 익숙한 도구에 유리할 수 있는 효과와 작업 순서 영향을 기록한다. 과목마다 같은 진단 문제를 다시 풀어 기억한 결과를 학습 효과로 취급하지 않는다.

| 확인할 항목 | 관측 방법 |
|---|---|
| 첫 개인화 가치까지의 마찰 | 자료 입력부터 첫 실제 학습 작업 완료까지의 시간·중단 위치 |
| 시험 범위와 정답의 신뢰성 | 학생과 검토자가 원문으로 범위·근거·정답·누락을 점검 |
| 실행으로 연결되는가 | 제안 카드 노출이나 클릭 외에 실제 작업 완료·미룸을 기록 |
| 개념이 남는가 | 일정 기간 뒤 처음 보는 동등한 난도 문제와 설명을 확인. 작은 파일럿으로 성적 향상 인과효과를 주장하지 않음 |
| 다시 선택하는가 | 해당 시험 준비 기간의 재사용, 다음 과목·다음 시험에서의 선택, 재사용 이유 |
| 기존 도구보다 나은가 | 설정·자료 찾기·검증 시간 및 오류를 기존 과정과 비교 |
| 비용을 지불할 이유가 있는가 | 실제 사용 후 기존 무료 대안과 비교한 선택 및 지불 의사를 확인 |

로그인·알림 클릭·AI 생성 횟수만으로 성공을 판정하지 않는다. 시험기간 수요와 학기 중 지속 수요는 따로 관찰한다. 이 파일럿에서 반복해서 확인된 문제를 다음 구현 범위로 좁히는 것이 타당하다.
