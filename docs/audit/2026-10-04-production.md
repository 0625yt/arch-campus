## 운영 예약 활성화와 실제 재개

- 운영 `JOB_WORKER_SECRET`를 등록하고 인증된 준비 상태·0041 이력을 확인한 뒤 `npm run worker:enable`을 실행했다. `arch-campus-material-job-recovery` 예약 하나가 활성 상태이며 주기는 `* * * * *`(1분)이다. URL과 키는 Vault에 암호화하고 예약 SQL은 비밀값 대신 Vault 이름을 참조한다.
- 별도 일회성 운영 검사는 임시 계정·짧은 가상 원문·과거 시작 시각의 `running / retry_count=0` 작업 하나만 생성했다. worker POST와 브라우저 작업 폴링을 호출하지 않고 DB 상태를 관찰했다. 운영 예약이 실행되어 `done / retry_count=1`, 재개·입력 재구성 이력, Cron SQL 성공, 요약 생성 하나와 캐시/작업 결과 일치를 확인했다. **6개 검사 통과**. 임시 계정과 연결 데이터만 삭제했으며 운영 예약은 활성 상태로 유지했다.
- 이는 가상 중단 상태의 예약 재개 검증이다. 실제 진행 중인 공급자 호출을 강제 종료한 시험은 아니며, 공급자 호출을 정확히 한 번 보장하거나 중간 토큰부터 이어가는 기능은 아니다. 한 번에 한 작업·자동 재시도 한 번이며 대기 작업이 많으면 복구가 늦어질 수 있다.
- 이번 실제 AI의 기록 기반 추정 비용은 장문 문서 `$0.020689`, 통계 `$0.022975`, 운영 예약 `$0.003458`, 합계 **$0.047122**(분류 포함)다. 공급자 청구서 금액은 아니다.

Google OAuth·메일/PKCE 왕복, MFA 복구 서버 지원, 외부 비용 알림, 푸시·외부 캘린더는 후속이다. Pro 가격·무료/Pro 한도·결제 제공자는 사용자 결정대로 추후 구체화한다.
