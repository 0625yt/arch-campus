## 가상 문제 생성 비교

원본 `4f3279c`의 공통+문제 MD와 새 MD를 같은 Gemini 3.5 Flash-Lite에서 비교했다. 통계·컴퓨터과학·일본어의 직접 작성한 가상 자료 3종, 각 6문항(객관식/단답형 각각 3 목표), 생성+현재 검수까지 측정했다. 양쪽에 같은 현재 검수기를 적용해 이전 운영 파이프라인 전체의 성능 비교로 해석하지 않는다.

| 자료 | 기존 통과/요청 | 새 통과/요청 | 기존 비용 USD | 새 비용 USD |
|---|---:|---:|---:|---:|
| 통계 | 6/6 | 6/6 | 0.011132 | 0.007657 |
| 컴퓨터과학 | 5/6 | 6/6 | 0.010754 | 0.008729 |
| 일본어 | 6/6 | 6/6 | 0.009866 | 0.006569 |
| 합계 | 17/18 | 18/18 | **0.031752** | **0.022954** |

- 새 문항 18개 모두 원문 그대로의 인용, 형식·문항 무결성·표면 중복·검수를 통과했다. 각 자료에서 두 종류의 문항을 확인했다.
- 이 실행에서 생성 입력 토큰 37,345 → 14,734(**60.5% 감소**), 생성+검수 예상 비용 **27.7% 감소**. 총 지연 24.1초 → 21.6초는 3개 자료의 실행 시간을 합한 값이며 SLA가 아니다.
- 비용은 저장소 `estimateCost()` 단가와 응답 usage의 추정치다. 제공자 청구서·환율·분류·임베딩·보충·OCR·Storage 비용은 포함하지 않는다. 실제 학기별 운영 비용의 보장 수치로 쓰지 않는다.
- 소규모 1회 비교이므로 통계적 우위나 실제 학업 성과가 증명된 것은 아니다. 긴 자료·다른 학과·서술형 출제·주입 공격·높은 동시성은 별도 평가가 필요하다.

초기 비교에서는 새 성공 JSON의 reason=null 파싱 실패를 발견해 계약을 바로잡았다. 다른 반복에서는 기존 JSON 자체의 구문 오류, 새 어학 문항의 길이 오류, 원어가 혼합된 해설도 관찰했다. 통과 기준은 낮추지 않고 계약·프롬프트·검증을 수정했다. 마지막 완료 실행을 위 표에 기록했으며 이전 실패가 없었다는 뜻은 아니다. AI 출력의 변동성 때문에 런타임 검증을 유지한다.

## 추가 검증과 운영 경계

- 실제 AI 골드 사례: 정답 검수·의미가 같은 단답·완전한 서술 인정, 복수 정답·근거 불일치·키워드 나열·반대 설명 거부.
- 요약은 가상 통계 자료에서 원문 인용·쪽수·뒤쪽 오류 구분을 확인했다. 중간 반복에서 최소 블록 수 미달과 인용 불일치를 발견해 스키마·출처 검사를 연결했다. 모든 요약 주장에 대한 독립 의미 검수는 아직 없다.
- 가상 과제 공지의 체크리스트 인용, 모호한 회식 날짜 제외, 분모 없는 30점의 weight_percent=null, 정확한 과제 마감 KST 변환을 확인했다. 일정 비율 귀속의 모든 표현을 지원하는 파서는 아니다.
- SDK 형식 오류에서도 이미 청구된 토큰을 보존한다. 문항 파서는 정상 항목만 복구할 수 있지만 최종 검수는 생략하지 않는다. 모든 provider 오류의 비용 복구를 보장하지는 않는다.
- 새 API 키·마이그레이션·라이브러리 없이 적용. 기존 보충 횟수와 모델 라우팅은 유지했다.

## 최종 검증 기록

- 타입 검사, 단위 **375 통과 / 외부 AI 11 생략**, 문서 링크 **105개 / 오류 0개**, diff 공백 검사 통과.
- 실제 AI: 문제 비교 1개, 검수·의미/서술 채점 2개, 요약·체크리스트·일정 3개 테스트 통과. 요약 인용의 줄바꿈 차이는 위치 확인 후 실제 원문 구간으로 복원한다. 일치 기준을 낮춰 통과시킨 것이 아니라 저장/표시할 인용을 바로잡았다.
- 모바일·태블릿·노트북 화면 **66 통과 / 전용 인증 검사 3 생략**. 로컬 예시·일부 가짜 응답을 사용하는 검사이며 전체 AI 검증을 대신하지 않는다.
- 임시 인증 계정으로 실제 API → 요약 작업/출처 저장 → 3문항 생성·검수·저장 → 일정 초안(날짜·배점) 흐름 통과. 로컬 서버가 실제 Supabase와 기존 AI 키를 사용했다. 임시 계정과 생성 데이터 삭제 완료.
- Biome 전체 오류 0개를 목표로 기존 성적 CSS의 형식 오류 1건도 정리했다. 전체 규칙 검사 **오류 0 / 경고 145 / 안내 9**. 경고 정리는 남은 작업이다.
- 프로덕션 빌드 통과, 전체 의존성 취약점 0개. 운영 배포에서는 임시 계정의 생성·저장과 기존 모바일 학습·백업 흐름을 다시 확인한다.
