# 장문 요약 인용·서버 작업 복구 — 2026-10-04

[실행 워크플로](../EXECUTION-WORKFLOW.md)의 다음 두 작업을 순서대로 진행했다. 이전 비용·결과 저장 검사는 [앞선 보고서](2026-10-04-workflow.md)에 남긴다. 운영 코드 배포와 전역 예약 활성화는 완료하지 않았다.

## 장문 요약의 실제 탈락 원인

- 가상 68K자 자료의 첫 진단은 2/2 구간 모두 원문 인용 검사에서 실패했다. 기록 기반 추정 비용 $0.019693. 두 번째 진단은 1/2 통과, $0.019718. 실패한 응답의 제목 인용은 실제 원문의 `원본 접수`였고 다른 인용은 실제 문장들이었다.
- 공통 원문 위치 검사기가 공백·기호를 제외한 8글자 미만을 거절해 실제 4글자 제목 때문에 해당 구간 전체가 탈락했다. 요약의 h2만 최소 2글자 제목을 실제 원문에서 확인하도록 했다. 원문에 없는 제목은 계속 거절하고 본문·문제 근거의 기존 8글자 기준은 유지한다. 모호하게 반복된 인용의 쪽수는 계속 null이다.
- 관련 단위 19개 통과. 짧은 실제 제목·잘못된 제목·짧은 본문 근거의 경계를 추가로 검사했다.
- 수정 직후 실제 API의 2/2 구간과 비용·캐시·범위 3개 통과, $0.020417. 이어서 문서 관리와 통계 자료 두 종류에서 각각 2/2 구간·원문 인용·핵심 개념/조건·비용·저장 검사 4개씩 통과, 각각 $0.020240/$0.022734.
- 위 다섯 실행의 기록 기반 추정 비용 합계는 **$0.102802**(분류 포함). 공급자 청구서 금액은 아니다. 모든 임시 계정·자료·작업·생성 기록·버킷을 삭제했다. 긴 실제 강의·더 큰 표본·전문가 평가는 이 가상 회귀와 구분한다.

## 화면을 열지 않아도 재개하는 서버 경로

- `POST /api/internal/material-jobs/recover`는 32자 이상 서버 비밀 키를 요구한다. 키 누락/짧음은 503, 잘못된 키는 401, 잘못된 범위는 400이다. 일반 로그인이나 클라이언트 키로 호출하지 않는다. `GET`은 인증된 준비 상태 확인만 하며 작업을 선점하지 않는다. 응답은 private/no-store이며 작업 본문·사용자 ID·결과를 반환하지 않는다.
- [0041](../../supabase/migrations/0041_material_job_worker.sql)은 서비스 역할만 호출할 수 있는 행 잠금/skip locked 선점 RPC를 추가한다. 8분 이상 멈춘 요약/문제를 한 번에 하나만 처리한다. 최초 실행은 retry_count=1로 선점하고 저장 입력과 DB 소유자로 재구성한다. 재시도도 멈췄다면 오류로 종료하며 무제한 재청구하지 않는다. 기존 0040 결과/완료 트랜잭션과 비용 예약을 재사용한다.
- 0041 및 pg_cron/pg_net을 API와 DB 프로젝트를 확인한 연결 DB/이력에 추가했다. cron/net 스키마는 public/anon/authenticated 사용을 거절한다. 기존 사용자 행과 운영 예약은 변경하지 않았다.
- 임시 스키마에 jobs를 복제해 실제 전역 선점을 검사했다. **독립 연결 20개가 작업 하나만 선점**, 잠긴 행 건너뛰기·소유자 범위·새 실행 보호·종료된 작업·지원하지 않는 도구·재시도 중단 종료·권한 등 **15개 통과**. 전역 SQL 검사도 실제 사용자 작업과 분리했으며 스키마 삭제 완료.
- 라우트 단위 **8개**, 실제 로컬 HTTP **10개 통과**. 동시에 HTTP 10개가 재개 한 번, 다른 계정 유지, 저장 입력 재구성/진행 이력, 빈 자료와 종료된 재시도의 AI/예약 0개 확인. 임시 계정 2개와 데이터 삭제 완료. 이 HTTP 검사는 브라우저 폴링을 호출하지 않는다.
- `worker:enable`은 운영 HTTPS 주소의 인증된 준비 상태와 0041 이력을 확인한 뒤 Vault에 키를 암호화해서 보관하고 1분마다 호출한다. `worker:disable`은 해당 앱의 예약만 해제한다. 운영의 준비 상태가 404여서 활성화 전 검사에서 거절됐고 전역 예약 수 0을 재확인했다. 로컬/현재 Preview 브랜치 실행 키만 준비했다. 실제 운영 배포·같은 키 설정·예약 활성화는 남아 있다.
- [Supabase Cron](https://supabase.com/docs/guides/cron)과 [pg_net](https://supabase.com/docs/guides/database/extensions/pg_net), [Vault 예약 호출 예제](https://supabase.com/docs/guides/functions/schedule-functions)를 기준으로 구현했다. 새 외부 실행 서비스 계정은 추가하지 않았다.

## 전체 품질·배포 범위

로컬 전체 검사: 단위 **444개 / 외부 AI 16개 기본 생략**, 화면 **75개 / 인증 3개 기본 생략**, 타입·빌드·문서·보안 통과. Biome 오류·경고·안내 0, 취약점 0. 이후 검사 도구의 fixture 제목/정리 표시와 단위 환경 복원을 정리하고 관련 단위를 다시 확인했다. 제품 동작은 바꾸지 않았다.

Preview의 서버 API·DB 예약 호출·실제 AI 결과와 최신 원격 CI는 후속 증거 및 [PR #4 검사](https://github.com/0625yt/arch-campus/pull/4/checks)를 따른다. 운영에는 새 코드를 배포하지 않았다. 예약이 활성화돼 있어야 화면 없는 자동 복구가 동작한다. 한 번 재시도 후에는 오류로 종료한다. 공급자 호출을 정확히 한 번으로 보장하거나 중단된 모델 응답의 중간 토큰에서 이어가는 기능은 아니다. 한 호출당 작업 하나를 처리하므로 대기 작업이 많으면 복구가 늦어질 수 있다.

- 미리보기 장문 품질도 두 자료에서 각각 **2/2 구간·4개 검사**, 총 **8개 통과**. 기록 기반 추정 비용은 $0.020080/$0.022989. 이번 보고서의 로컬/미리보기 AI 평가 전체 기록 합계는 **$0.149733**, 공급자 청구서 확인 금액은 아니다.

## 재개·실행 명령

```bash
npm run test:summary-quality-live
npm run workflow:worker
E2E_BASE_URL=<검증된-Preview-주소> npm run test:job-worker-schedule
E2E_BASE_URL=<검증된-Preview-주소> npm run test:job-worker-schedule-live

```

품질 평가와 schedule-live는 실제 AI 비용이 발생한다. 예약 검사는 가상 중단 상태와 임시 계정 하나로 범위를 제한하며 전역 운영 예약을 만들지 않는다. 검사 후 해당 예약·HTTP 요청/응답·Vault 항목·계정을 삭제한다. 빈 자료 예약 검사는 AI 호출이 없다. 기본 CI에는 실제 DB/AI 검사를 포함하지 않는다.
