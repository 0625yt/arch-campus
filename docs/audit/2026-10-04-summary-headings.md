# 생성한 소제목과 원문 인용 구분 — 2026-10-04

[앞선 운영 배포](2026-10-04-production.md) 이후 신고된 요약 실패를 확인했다. AI 응답은 유효한 JSON이었지만, 표지 문구를 합친 제목과 서로 다른 단원 제목을 이어 붙인 제목을 실제 원문 인용처럼 반환했다. 원문에 없는 두 인용 때문에 전체 요약을 거절한 사례다.

## 보완 범위

- [인용 위치 검사](../../src/lib/summary-grounding.ts)는 h2의 인용을 실제 원문에서 찾으면 원문 인용·쪽수를 보존한다. 찾지 못한 경우 h2의 `sourceQuote`와 `sourcePage`만 null로 정리하고 소제목과 정상 본문은 유지한다. 가짜 인용을 저장하거나 다른 블록의 쪽수를 빌려오지 않는다.
- para·bullets·callout의 원문에 없는 인용과 공백·기호를 제외한 8글자 미만의 근거는 계속 거절한다. 모든 요약 주장에 대한 의미 검수는 이 위치 검사 범위에 포함되지 않는다.
- [요약 프롬프트 v4](../../src/prompts/summarize.md)는 표현을 바꾸거나 여러 단원을 묶은 소제목에 인용·쪽수를 null로 지정하고, 실제로 연속된 원문 제목만 인용하도록 명시한다.
- 추가 모델 호출·자동 재시도·모델 라우팅·DB 스키마 변경은 없다. 기존 원자적 결과 저장과 실제 호출별 비용 기록을 유지한다.

## 검증

- 저장된 실제 실패 응답과 원문을 읽기 전용으로 재검사했다. **12개 블록 유지·잘못된 h2 인용 2개 제거·실제 원문 인용 10개 보존**을 확인했다. 새 AI 호출·사용자 데이터 변경 없이 검사했으며 원문·응답·사용자 식별자를 저장소에 넣지 않았다.
- 관련 단위 28개 통과: 인용 검사 13개·원문 위치 검사 6개·[서비스 저장/비용 검사](../../src/lib/services/summarize-persistence.test.ts) 9개. 분리된 제목을 합친 경우, 정상 본문/쪽수 보존, 세 본문 블록 종류의 가짜/짧은 인용 차단, 잘못된 본문은 캐시/작업 결과를 저장하지 않는 경계를 확인한다.
- 전체 로컬 단위 **453개 통과 / 외부 AI 16개 기본 생략**, 타입·프로덕션 빌드·Biome 통과. 문서 링크 검사 통과. 화면 변경은 없으며 원격 전체 화면 검사와 운영 API 증거는 [PR #4 검사·설명](https://github.com/0625yt/arch-campus/pull/4)을 따른다.

이전 실패 작업은 당시의 오류 이력이다. 보완은 새 요약 생성과 저장에 적용되며 과거 오류 이력을 임의로 성공으로 바꾸지 않는다.
