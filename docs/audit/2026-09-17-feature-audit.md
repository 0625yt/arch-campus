## 결론

핵심 학습 흐름은 구현되어 있다. 다만 전체 서비스를 ‘완료’로 볼 수는 없다. MFA 강제, 운영 비용 보호, 실제 계정 간 격리 검증이 먼저 필요하다. 복습 스케줄·푸시·외부 캘린더·결제는 아직 실행 기능이 없다.

이번 점검은 로컬 코드·설정·테스트 기준이다. 이번 수정의 운영 배포는 하지 않았으며, 기존 운영 배포와 동일하다고 해석하면 안 된다. 마지막으로 확인한 기존 배포 커밋은 `498870a`이다.

## 이번 수정

1. **Next.js 16.2.11 → 16.3.3**: 공식 보안 수정 버전 적용. 의존성 경고는 실제 공격 발생의 증거와 다르다.
2. **OfficeParser 6.1.1 → 8.0.0**: 새 `ast.to("text")` API로 전환하고 가상 PPTX 파일의 한국어 텍스트 추출을 검사했다. Node.js 22.13 이상 필요, 프로젝트 실행은 24.x 권장.
3. **로그인 복귀 주소 검증**: 로그인·가입·OAuth callback에서 외부 URL·프로토콜 상대 URL·역슬래시·제어문자·잘못된 인코딩을 차단한다. 유효한 앱 내부 경로와 검색 조건은 유지한다.
4. **시간표 대비**: 어두운 테마의 작은 분 표시와 현재 시각 배지 대비를 개선했다.
5. **시간표 초기 시각**: 서버가 보낸 시각으로 첫 화면을 맞춘 뒤 기기의 시각으로 갱신한다. 서버/기기 시간 차이로 발생한 hydration 오류에 회귀 검사를 추가했다.
6. **환경 검사 정확도**: 실제 모델 라우팅 함수 재사용, 키 일부 출력 제거, 데이터 행 미출력, 익명 사용자 데이터 노출 판정 강화, 생성 없는 모델 가용성 검사.
7. **보안 화면 설명**: 미구현인 개별 세션 목록을 제공하는 것처럼 보이던 설명 수정.

9월 18일 후속 조사에서 npm 오류가 Vitest의 peer 의존성 처리 중 발생함을 확인했다. 이를 분리하고 호환 범위에서 AI SDK·XML 파서·brace-expansion·nanoid 등을 업데이트해 치명·높음·낮음 경고를 모두 제거했다. 전역 npm 변경이나 peer 검사 생략은 하지 않았다.

남은 중간 등급 4건은 Vitest/`@vitest/mocker` 2건과 ExcelJS/`uuid` 2건이다. Vitest 4.1.11 직접 설치도 동일한 npm `edgesOut` 오류로 실패했다. ExcelJS의 자동 수정 제안은 3.4.0으로의 주요 버전 다운그레이드여서 적용하지 않았다. 설치된 ExcelJS 소스에서 uuid 사용은 v4이며, 공지된 취약 경로는 버퍼를 전달하는 v3/v5/v6이다. 이 코드 확인을 취약점이 모두 해소됐다는 판정으로 확대하지 않는다. 후속으로 테스트 도구 설치 문제와 ExcelJS 의존성 교체를 검증해야 한다.
