# 서비스 효율 개선과 운영 반영 — 2026-10-15

사용자의 전체 서비스 점검·배포 요청으로 [AI·라이브러리 갱신](2026-10-15-upgrades.md), [요약·문제·채점 품질 개선](2026-10-15-study-quality.md), 공부 계획과 일정 알림을 함께 검증한다. 운영 주소 연결 결과는 아래 배포 항목에 기록한다.

## 추가 도입과 수정

- `p-limit` 7.3.3으로 PDF OCR을 최대 두 구간씩 실행한다. 분할 재시도도 이 한도 안에서 처리하며, 완료 순서와 관계없이 원래 페이지 순서로 합친다. [공식 API](https://github.com/sindresorhus/p-limit)의 동시 실행 제어를 사용한다. 별도 서비스 비용은 없다.
- 실제 PDF 검사에서 OCR에 기본 “JSON으로 답하라” 문구가 붙어 페이지 헤더 출력과 충돌했다. OCR 전용 평문 요청과 정확한 페이지 수를 전달해 불필요한 재귀 호출을 제거했다. 이미지·PDF 호출에도 모델별 temperature 호환 정책을 적용했다.
- OCR 응답이 길더라도 원문의 짧은 숫자·조건이 사라질 수 있으므로 길이 대신 실제 원문 포함 여부를 검사해 보강한다. unpdf에는 바이트를 직접 전달해 성공·실패 후 PDF worker를 정리하도록 했다.
- Anthropic 캐시 사용량을 SDK의 `inputTokenDetails`에서도 읽는다. 구조화 출력 실패 시에도 캐시 토큰과 청구 사용량을 보존한다. 기존 자료 프롬프트 캐시는 유지하며, 잘못된 비용 추정 때문에 예산을 과도하게 차감하는 경우를 줄인다.
- 채점 모델 실패 시 점수와 원래 판정을 보존하고 재확인 안내를 표시한다. 학생 답안이 포함될 수 있는 공급자 오류 원문은 로그에 출력하지 않는다.
- 단일·합본 업로드에서 선택한 과목의 소유권도 저장 전에 확인한다. 다른 계정의 과목 ID를 보내면 404로 거절하고 자료 행과 AI 작업을 만들지 않는다. 과목 확인 장애는 503으로 구분한다. 실제 프로덕션 모드 HTTP에서 두 경로의 차단과 저장된 자료 0개를 확인했다.
- 배포 제외 파일을 지정해 로컬 환경변수·가상 자료·PDF 결과·개인 도구 설정이 배포 소스에 섞이지 않게 했다.

새 AI SDK·PDF 뷰어·TypeScript 메이저 전환은 이번 개선에 필요하지 않아 기존 호환 패치 버전을 유지했다. 기존 Zod·AI SDK·Supabase·FSRS·PDF 라이브러리를 활용하며, 추가 벡터 DB나 외부 유료 서비스를 도입하지 않았다.

## 실제 OCR 측정

같은 가상 16쪽 PDF에 페이지별 고유 임계값과 Collect → Validate 도식을 넣어 비교했다. 수정 전에는 페이지 형식 오류로 15쪽이 원문 텍스트 대체 경고를 냈다. 수정 뒤에는 모든 쪽의 수치와 도식 문구를 추출했고 대체 경고가 없었다.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 공급자 호출 | 30회 | 2회 |
| 입력 토큰 | 57,286 | 10,144 |
| 출력 토큰 | 8,972 | 1,941 |
| 실제 처리 시간 | 30.7초 | 4.0초 |
| 코드 단가 추정 비용 | $0.03962 | $0.00790 |

이 표본에서 입력 토큰 약 82%, 추정 비용 약 80% 감소다. 수정 후 두 공급자 호출 시간 합계는 7.09초였고 실제 전체 시간은 4.01초였다. 일반적인 모든 PDF의 성능 향상률을 보장하는 수치는 아니다. 회귀 명령은 `npm run test:pdf-ocr-live`이며 실제 API 비용이 발생한다.

## 배포 전 확인

- 단위 검사 586개 통과, 외부 호출 검사 25개 기본 제외. 타입·빌드·Biome 경고 0·문서 링크 검사 통과. 루트와 HWP 변환 서버의 npm audit 취약점 0개.
- Playwright 114개 통과, 인증용 3개 기본 제외. 별도 임시 계정으로 인증된 화면 세 기기 검사 3개 통과.
- 실제 인증·격리 31개, API 격리와 알림 저장, 비밀번호 복구·재로그인·토큰 재사용 차단을 확인했다. 실제 사용자 메일·Google OAuth 왕복은 포함하지 않는다.
- DB: 알림 임시 스키마 22개, 공부 계획 임시 스키마 13개, RLS/MFA 29개 통과. 기존 사용자 데이터는 변경하지 않았다.
- 작업 복구 DB 12개·원자적 결과 저장 23개·복구 HTTP 흐름, 공유 요청 제한 HTTP 7개·서버 worker HTTP 10개 통과. 비로그인 401은 개발용 인증 폴백이 없는 프로덕션 모드에서 별도로 확인한다.
- 실제 AI: 자료 분류 2개, 문제 생성 전체 파이프라인 6회(간호·회계·장문 문서 각 2회), 채점·검수 2개, 요약·과제 인용·일정 추출 3개, PNG OCR 1개, 새 PDF OCR 1개 통과. 요약 검사 한 곳은 서비스와 달리 서버 전용 coverage까지 요청해 공급자 grammar 한도를 넘겼다. 실제 서비스와 같은 생성 전용 스키마로 수정한 뒤 통과했다.
- 정답 직접 인정 API는 프로덕션 모드에서 비로그인·다른 소유자 거절, 원판정 보존·저장·오답 뷰 제외·되돌리기·계정 정리 6개 통과.

## 운영 적용

- 연결된 Supabase 프로젝트를 확인하고 새 0042·0043을 각각 트랜잭션으로 적용했다. 마이그레이션 SQL과 이력을 함께 저장했다. 기존 적용 파일과 사용자 자료는 수정하지 않았다.
- 운영에 요약·출제 Haiku 5.5, 요약 검수 Gemini 3.8 Flash, 문제 검수·보조 채점 Flash-Lite를 기능별 모델 ID로 명시했다. 기존 전역 vendor 설정과 관계없이 검증한 기능별 모델을 사용한다.
- 알림용 VAPID 키와 별도 worker 키를 생성해 민감 환경변수로 등록했다. 사용자의 브라우저 알림 동의는 자동으로 요청하지 않는다.
- 배포본의 실제 HTTP 검증·서비스 주소 연결·운영 예약 활성화는 후속 결과에 기록한다. 실제 스마트폰의 알림 수신은 자동 검사와 별개다.
