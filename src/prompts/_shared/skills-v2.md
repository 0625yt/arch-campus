# 프롬프트 유지보수 가이드 — 2026-10-01

이 문서는 개발용이며 `loadPrompt()`의 런타임 주입 대상이 아니다. 실제 공통 규칙은 [master-rules](master-rules.md), 실제 컨텍스트 사용 규칙은 [persona-schema](persona-schema.md)다.

## 작성 순서

1. 도구의 실제 입력·출력 스키마와 호출 경로를 확인한다. MD 헤더의 모델 이름으로 운영 모델을 판단하지 않는다.
2. 무엇을 근거로 답할 수 있는지와 정보가 없을 때의 null·제외·거부 동작을 먼저 정한다.
3. 자료 → 근거 → 답 → 검증 순서를 명확히 한다. 자료 인용·수치·전문 용어는 말투 규칙보다 우선이다.
4. 실제로 틀릴 수 있는 경계 사례를 담은 짧고 올바른 예시를 추가한다. 예시 자체가 복수 정답이거나 가짜 출처가 아닌지 검사한다.
5. JSON 도구는 실제 Zod 스키마와 일치시킨다. 구조화 출력은 형식 검증이며 정답·근거 검증을 대신하지 않는다.
6. 허가된 가상·공개 평가 자료로 품질·비용·시간을 함께 확인한다. 호출자에게 필요한 검사를 우회해 산출률만 높이지 않는다.

## 비용·품질 기준

- 불필요한 공통 문서·중복 지시·장문 예시를 줄인다. 캐시를 맞추기 위해 프롬프트를 늘리지 않는다.
- 기본 모델을 바꾸기 전 자료 근거·정답 유일성·범위·다양성·사용 가능한 문항당 비용을 비교한다.
- 모델 자신이 평가한 통과율을 실제 학생 학습 효과·시험 변별력으로 해석하지 않는다.
- 모든 프롬프트 변경은 날짜·의도·평가 조건·한계를 [프롬프트 운영 문서](../../../docs/PROMPTS.md)에 남긴다.
